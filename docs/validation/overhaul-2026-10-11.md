`ae94c721f2f2124a9fbd675c3ba3cd780fe54644`. The original audit inputs and the
local progress ledger are excluded from Git. No hardware was flashed or probed.

followed by staged implementation and independent reviews of the ownership,
hardware/dependency, acquisition, persistence, telemetry and benchmark changes.

## Material findings from the follow-up review

These corrections include defects in the earlier implementation, migration
hazards and weaknesses in its verification. The corresponding tests were
reproduced before the relevant correction where the defect was host-executable.

| Area | Review result and correction |
|---|---|
| Graphs and headers | Odd-position spikes and a single sample were missing; rounded FPS and popup restoration could leave stale buffer pixels. Actual pixel tests now cover these cases, constant/nonfinite history and both buffers. |
| Samples and concurrency | Extrema must begin at the first valid sample, including negative values. Statistics now advance before latest-value publication; coalesced Watch deliveries cannot erase between-frame peaks. Reset success requires acknowledgement. |
| Framebuffer and DMA | Removed raw alignment assumptions and global reusable buffer access. Fixed rectangle intermediate overflow. Affine ownership and exact generation tokens prevent stale completion release; active DMA is never cancelled to recover a buffer. |
| Runtime and linker | Corrected the RP2350 watchdog reset mask and a migrated linker-counter placement that put stack/heap bounds in flash. Input batches, render slices and owner deadlines are finite; linked addresses are checked directly. |
| UART | Reviewed upstream wakeup/wrap fixes and added sticky error handling, bounded FIFO work, static storage, core ownership and non-Send/non-Sync handles. Positive and negative target API compilation guards cover ownership escapes. |
| Diagnostics | Foreign single frames cannot abort active segmented responses or extend their deadline. TX/flow-control tokens are current-generation only. Capability, negative, malformed, pending and timeout paths retain honest quality and bounded retries. |
| Flash | Core1 lockout originally executed from flash. Four final critical functions are inspected and byte-gated in SRAM, with full startup-copy checks. Maintenance drains the complete UART command, finishes I2C and owns both idle display buffers before writing. |
| Journal | Future integrity-valid versions cannot be mistaken for corrupt space. Tests cover every program-byte cut, erase-prefix cut, record bit flip and representative torn patterns, read/write failures, ambiguous generations and bounded save retries. |
| Telemetry | Correlated coherent input batches with displayed content; excluded inputs hidden by critical overlays. Histograms use successful software completions and explicit windows. Checked actual Rust output against parser failure/truncation/saturation cases. |
| Benchmark/tooling | Removed workload dependence on preceding cases, added missing output checks and full coverage fixtures. Fixed omitted capture inputs, stale/shared ELF path races and Python assertions that vanished under optimization. |
| Electrical and protocol claims | Corrected USB/VSYS backfeed and supply assumptions, RGB565 expansion and clock reporting. The opaque U-DNU profile does not establish a DID, scaling or exact ECU identification. |

Hardware-controlling changes were reconciled with chip/board documentation,
primary implementations and the exact locked HAL/crate code, including linked
ARM disassembly for flash and target benchmarks. The source references and
reviewed upstream issues live beside each subsystem's implementation record.
Unresolved upstream warnings, including RP2350 timer-alarm behavior and
`proc-macro-error2` future compatibility, remain explicit in the dependency review.

## Hardware handoff

1. Inspect the exact board revisions, rails, power switch/USB isolation,
   regulator EN, UART levels and CAN termination using the wiring record.
2. On an isolated bench supply, verify stock startup, watchdog reset causes,
   PWM, SPI/CS/RGB565/TE, encoder direction/disconnect and both-core progress.
3. Qualify the adapter firmware's actual framing/metadata contract before
   enabling any diagnostic request profile. The shipped Longan profile is
   unqualified and sends no CAN queries; it never fabricates live data.
4. Capture ECU/TCU IDs and timestamped read-only raw responses on the actual
   DNUC vehicle, then compare each quantity, source and scaling with a trusted
   diagnostic reading. Keep unsupported EGT, DSG, boost and lambda unavailable.
5. Capture warmed software/physical display traces and finite target-kernel
   records tied to the exact ELF, clocks and power conditions. Compare full,
   retained/partial and serial fallback modes on the same scene.
6. Exercise fault injection, ignition/sleep/reconnect, journal power cuts and
   extended thermal/sparse-event soak before considering installed acceptance.

No measurement in this report substitutes for those steps.
