The following checks passed on the dated compiler and refreshed locks:

- `cargo check --locked --manifest-path studio-helper/Cargo.toml`
- `cargo check --locked --manifest-path host/Cargo.toml --tests`
- `cargo check --locked --manifest-path configurator/Cargo.toml --target wasm32-unknown-unknown --bins`

The browser check required removing a duplicate `mod project_io;` declaration
in the integration baseline; that source repair is separate from this update.
ARM compilation still reports the vendored `cortex_m_rt::pre_init` deprecation
and the build-time `proc-macro-error2` private `proc_macro` re-export future
incompatibility. The latter is tracked by [upstream issue 13](https://github.com/GnomedDev/proc-macro-error-2/issues/13)
and [open fix 14](https://github.com/GnomedDev/proc-macro-error-2/pull/14);
[PIO PR 85](https://github.com/rp-rs/pio-rs/pull/85) removes the dependency in
PIO 0.4.0. These warnings are not suppressed or represented as resolved.

This refresh does
not establish browser interaction correctness, hardware behavior, ELF/UF2
layout, flash safety or release performance. The combined final validation run
remains responsible for those applicable gates. Historical dated validation
reports retain the compiler versions actually used for those runs.

### RTT policy follow-up

The logging gate now pins the reviewed `defmt-rtt` 1.3.1 resolved graph.
Comparison of the published 1.3.0 and 1.3.1 crate `src/` trees found one
source change: `channel.rs::write_all` advances with
`bytes.get_unchecked(consumed..)` instead of checked slicing. Both selected
write functions return `write_impl`'s `bytes.len().min(available)` (or zero),
so this advances within the input slice. Encoder ownership, host flag handling,
and flush behavior are unchanged. `disable-blocking-mode` remains mandatory;
`drop-on-contention` and application `defmt::flush` imports/calls remain rejected.
Tests reject adjacent unreviewed versions and either unsafe feature graph.
Published source: <https://docs.rs/crate/defmt-rtt/1.3.1/source/src/channel.rs>.
