# P-256 security dependency review, 2 November 2026

The pairing-enabled dashboard moves from `p256 0.13.2` to stable `0.14.0` to
remove its `crypto-bigint 0.5.5` dependency covered by
[RUSTSEC-2026-0387](https://rustsec.org/advisories/RUSTSEC-2026-0387.html).
The advisory reports compiler/target-dependent timing variability in operations
intended to be constant time and lists `>=0.7.6` as patched. This review does not
establish secret extraction or an observable radio timing attack on the RP2350.
The standalone probe and NGM utility retain their no-security feature guard.

## Scope and compatibility

Only the P-256 dependency closure and the private Trouble cryptography adapter
change. `p256` keeps `default-features = false` and the existing `ecdh` and
`arithmetic` features. No new tables, allocator, OS entropy source, pairing mode,
wire format or persistent bond storage is enabled. Trouble's callers continue
using `rand_core 0.6`; the adapter draws complete 32-byte candidates and accepts
only nonzero scalars below the subgroup order. It never reduces random bytes
modulo the order. As before, rejection sampling assumes rejected random outputs
are unrelated to later outputs; a broken RNG can loop indefinitely or panic.
The explicit candidate buffer is zeroized after parsing. This does not promise
erasure of every backend or compiler-generated temporary copy.

SEC1 API names change, while both point validations, Bluetooth debug-point
rejection and the equal-X-coordinate exclusion remain. Public keys and shared
secrets preserve their existing byte order and bounded representation.
The optional Cortex-M4 backend is not selected for this Cortex-M33 board.

The published `p256 0.14.0` source identifies commit
`27e62fdf973ef5f1b0a81d4577bec0aa323cde5f`; `elliptic-curve 0.14.3` identifies
`8fffd5b1e6c5b9272b18efa967c55a8bd78d0d9b`. The current patched
`crypto-bigint 0.7.10` identifies `55af01b1957b1f90d718bf697ea9a6db7287151c`.
Its release notes mark 0.7.6, 0.7.7 and 0.7.8 as yanked following a `NonZero`
multiplication trait correction; the older version suggested in Trouble issue724
must not be copied as a fresh pin. The dated repository nightly remains unchanged.

## Source assessment

The old selected P-256 field arithmetic used its own 32-bit Montgomery backend
and widened arithmetic helpers; not every primitive named by the advisory was
on the selected ECDH path. Scalar generation did use `crypto-bigint` comparison
and subtraction. This distinction limits an exploit claim; it does not establish
that an advisory-flagged dependency is safe for this target.

The new release changes more than API spelling: field inversion delegates to
`primefield`/`crypto-bigint`. Existing image, RAM and stack admission therefore
remain required. The upstream cryptography documentation also cautions that its
arithmetic has not received a complete independent constant-time assessment.
Host vector tests do not prove generated Cortex-M33 instructions are constant time.

[Upstream P-256 release notes](https://github.com/RustCrypto/elliptic-curves/blob/p256/v0.14.0/p256/CHANGELOG.md),
[patched bigint release notes](https://github.com/RustCrypto/crypto-bigint/blob/55af01b1957b1f90d718bf697ea9a6db7287151c/CHANGELOG.md),
and [Trouble release request724](https://github.com/embassy-rs/trouble/issues/724)
were checked against actual package source. The four ATT fixes referenced by that
request are already covered by this repository's earlier local hardening:
request/response length and tuple admission, checked queued-write offsets,
ReadBlob offset rejection, and the 23-byte MTU floor. No new peer-triggered ATT
panic was established from that request.

## Verification

Before migration, all21 focused cryptography tests passed, including new
characterizations through the actual key-generation wrapper: reject zero,
subgroup order and all-ones before accepting scalar one; retain order-minus-one;
and reject invalid local or remote affine points. The scalar-one test compares
against literal P-256 generator coordinates. Existing Bluetooth ECDH/f5 vectors,
equal-X rejection and size assertions remain unchanged.

At the migration checkpoint, serialized native library suites passed: 303 selected-security,
248 discovery-no-security and 335 default/scan/legacy/queued-write tests. Strict
all-target Clippy passed (Cargo separately reported the existing unused
`static_cell` manifest warning), as did warning-denied private security rustdoc.
The21 focused cryptography tests passed again after the final mechanical lint
correction. Final selected Cortex-M33 dashboard Clippy and private documentation
also passed, including the pairing-enabled and target-benchmark contexts.
The final 280/70 traced BLE dashboard also passes source-bound practical M33
image admission: 457600 static RAM bytes, 66688 bytes of core-0 headroom, and a
21016-byte conservative radio path bound. The unchanged headroom floor is 65536
bytes; the unchanged core-0 reserve is 8192 bytes. The new
[stack-shape derivation](../performance/memory-layout.md#reviewed-p256-014-stack-shape-2026-11-02)
retains required arithmetic boundaries, the fixed child allowance and legacy
fixtures. Exact image identities and the other build results belong to the
[full audit](../validation/full-firmware-audit-2026-11-02.md).
No physical pairing, entropy, side-channel, flash or vehicle qualification
follows from these software tests.
