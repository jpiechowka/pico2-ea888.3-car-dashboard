# Maintenance dependency review, 18 October 2026

Historical checkpoint. The [20 October full audit](full-code-audit-2026-10-20.md)
records the later HAL/radio/linker changes; its
[validation record](../validation/full-code-audit-2026-10-20.md)

## Compiler and compatible updates

`rustup update` completed, followed by installation of the reproducible
`nightly-2026-10-18` pin: rustc `1.101.0-nightly`, commit
`8006091eb71ae7d9e9bccb66c6122c9d68af4466`, LLVM 23.1.4. Root, host,
firmware and CI use this date; Studio/helper inherit the root pin. ARM remains
`thumbv8m.main-none-eabihf` with `-C target-cpu=cortex-m33`. Benchmarks in this
maintenance pass compare both versions using this same compiler.
[Official dated manifest](https://static.rust-lang.org/dist/2026-10-18/channel-rust-nightly.toml).

All 42 direct registry dependencies present at the audit baseline matched the
latest stable releases. The release lookup also covered all 405 resolved crate
names across the five workspace lockfiles and four pinned Cargo build tools.
All-feature Cargo metadata identifies the exact parent constraints in the
[resolved-version table](constraints-2026-10-18.md). Older incompatible families
remain where upstream requirements or shared resolution require them; this is
not a claim that every transitive package has the numerically highest version.

The new host-only provenance verifier adds `tar =0.4.46` and promotes the already
resolved `flate2 =1.1.10` to a direct dependency. Its `filetime 0.2.29` transitive
dependency was also checked against official release metadata: the integrated
inventory contains **44 direct and 407 resolved registry crate names**. Neither
archive library enters the firmware or Wasm dependency graph. Tar default
features are disabled; validation streams entries without extracting them.
The actual locked tar iterator and gzip decoder implementations were reviewed
for entry types, duplicate paths, byte limits, trailers and premature EOF.
[tar source](https://docs.rs/crate/tar/0.4.46/source/src/archive.rs),
[flate2 source](https://docs.rs/crate/flate2/1.1.10/source/src/gz/bufread.rs).

The compatible lockfile update is **libc 0.2.190 -> 0.2.191**. The published source
diff and build script were reviewed against the [official release](https://github.com/rust-lang/libc/releases/tag/0.2.191):
Emscripten ABI version selection, FreeBSD/AIX corrections, Apple bindings and
additional platform constants. There are no changed Windows runtime bindings in
that diff. No application API migration was needed. Bare-metal Pico firmware does
not acquire a libc runtime through this update.

## Verification boundaries

Native unit/integration tests, strict nightly Clippy, Wasm/browser failures and
practical linked ARM image checks are the integration gates. The new dated pin
requires fresh checks; historical green CI is not evidence for a changed graph.
The current workflow records its exact commit and separate platform jobs.
Neither dependency review nor those software checks qualify BLE radio behavior,
DNUC measurements, physical FPS, electrical margins or the deferred instruction proof.
