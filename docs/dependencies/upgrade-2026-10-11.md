## Release and source decisions

- `heapless` 0.9.3 addresses container panic-safety defects according to its
  [upstream changelog](https://github.com/rust-embedded/heapless/blob/main/CHANGELOG.md).
  The application uses `heapless::String` APIs unchanged; both target and host
  builds compile. The candidate host timing is recorded in
  `docs/performance/dependency-upgrades.md`.
- `cortex-m-rt` 0.7.6 adds optional Armv8-M MSPLIM initialization and startup
  fixes; 0.7.7 aligns `_stext` and changes the macro dependency to `syn` 3.
  These are listed in the [upstream changelog](https://github.com/rust-embedded/cortex-m/blob/master/cortex-m-rt/CHANGELOG.md)
  and confirmed in the downloaded 0.7.7 crate. No new optional startup
  feature was enabled. Stock and 300/75 release images compile on the pinned
  nightly. This does not establish correct startup on the physical RP2350.
- The [defmt 1.1.1 releases](https://github.com/knurling-rs/defmt/releases)
  add macro fixes and formatting support. The downloaded `defmt-rtt` 1.3.0
  source adds `drop-on-contention`, but its source warns that the mode
  identifies thread mode by `IPSR == 0`; on the two-core design, that is not
  a safe substitute for the HAL's multicore critical section. Keep its
  default critical-section mode during the dependency update and design
  nonblocking logging separately. Stock and 300/75 release images compile;
  physical RTT decoding and contention behavior remain untested. Strict
  Clippy still stops on the pre-existing `needless_range_loop` diagnostic.
- Embassy's [RP examples manifest](https://github.com/embassy-rs/embassy/blob/main/examples/rp/Cargo.toml)
  confirms the published 0.10.0 / 0.8.0 / 0.5.1 family. The open
  [RP2350 timer-alarm issue #6528](https://github.com/embassy-rs/embassy/issues/6528)
  describes a plausible lost alarm in 0.10.0; the report has no linked fix.
  A firmware watchdog and hardware trace remain necessary. The default
  `defmt-rtt` critical section uses the HAL implementation, not a single-core
  interrupt-only lock. The downloaded `embassy-rp` 0.10.0
  `critical_section_impl.rs` reserves hardware spinlock 31, records the owning
  core, and disables local interrupts while held. This also meets the
  [cortex-m 0.7.8+ multicore requirement](https://github.com/rust-embedded/cortex-m/releases)
  for a genuine cross-core critical section after the transitive refresh to
  `cortex-m` 0.7.9.

## Lockfile and CI refresh

`cargo update` selected 51 newer compatible firmware packages and removed a
second `heapless` 0.8.0 copy. The host lockfile was already at its highest
compatible versions. Three firmware packages remain behind a published
stable version, with confirmed resolver constraints:

| Package | Locked / available | Reason |
| --- | --- | --- |
| `az` | 1.2.1 / 1.3.0 | `embedded-graphics` 0.8.2 requires `~1.2.0` |
| `fixed` | 1.29.0 / 1.31.0 | 1.31.0 requires `az ^1.3`, conflicting with the graphics requirement |
| `generic-array` | 0.14.7 / 0.14.9 | `crypto-common` 0.1.7 requires `=0.14.7` through the PIO parser build chain |

These were confirmed with `cargo update -p <name> --precise <latest> --dry-run`
and `cargo tree --invert <name>`. The host graph has the same `az` constraint.
Forcing these with a patch would change upstream compatibility assumptions.

`proc-macro-error2` 2.0.1 is the newest release and triggers Rust's
[future-compatibility warning E0365](https://github.com/rust-lang/rust/issues/127909)
for a private `proc_macro` re-export. It still compiles on the pinned nightly;
this needs a future upstream release or a separately reviewed patch.

CI now uses [checkout 7.0.1](https://github.com/actions/checkout/releases),
[rust-cache 2.9.2](https://github.com/Swatinem/rust-cache/releases), and the
[rust-toolchain action's documented toolchain input](https://github.com/dtolnay/rust-toolchain)
to select the same `nightly-2026-10-10` as local builds. Dependabot now covers
the host crate. No GitHub runner execution has been observed locally.

The first refreshed firmware build reported a `.text` alignment warning:
`memory.x` overrode `_stext` at a four-byte-only address after the RP2350 boot
info. The new `cortex-m-rt` changelog assigns alignment responsibility to
overrides. Aligning `_stext` to 16 bytes removed the linker warning in the
stock compile; this still needs a physical boot test.

The host correctness suite still has the audited 4 pass / 6 known failures
after the two completed crate groups. Dependencies alone do not address those
rendering defects.
