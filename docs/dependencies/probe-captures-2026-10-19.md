# Probe capture dependency and admission review

Review date: 2026-10-19. Scope: bounded selected-peer capture, flash journal,
read-only USB recovery and host decoding. This adds no adapter profile, pairing,
proprietary authentication or ECU traffic. Prior radio sources remain documented
in [the radio review](radio-review-2026-10-18.md); current lockfiles and vendor
provenance manifests are authoritative.

Disabling serialport's default features avoids requiring libudev for this host

The resolved serialport Windows `enumerate.rs` obtains VID/PID from hardware
identifiers, but `product` from `SPDRP_FRIENDLYNAME`. A generic Windows serial name
therefore requires explicit `--port`; it is not proof that the firmware's USB
descriptor is missing. No port is opened to guess its protocol. Windows `com.rs`
uses synchronous ReadFile/WriteFile and `SetCommTimeouts`; the CLI sets 250 ms
individual I/O timeouts and a five-second complete-transaction deadline. It never
calls serial flush, whose implementation uses `FlushFileBuffers`. No background
thread or cloned serial handle remains after the command exits.

Firmware [USB ownership](../../firmware/ble-probe/src/usb.rs) uses bounded endpoint
packets, a separate capture byte lease and two-second write waits. Failed output
abandons the USB configuration epoch; a bus reset/replug is required before new
replies. The storage owner returns the byte lease before USB waits for the host.
No BLE request is generated by listing/exporting and USB has no mutation command.
Driver cancellation and OS timeout behavior remain part of physical qualification.

The 2026-10-20 [host handoff projection](../vehicle/ble-capture-studio-handoff.md)
normalizes validated records without expanding the firmware payload. SHA256
identifies the complete binary, not its authenticity; a frozen fixture hash was
independently computed with Python hashlib. JSON hints do not enable a profile,
cache handles or establish permissions. Slot/generation envelope admission rejects
invalid or partially specified pairs before any output directory is created.

## Shared formats and journal

The pure `no_std` [capture codec](../../crates/dashboard-core/src/discovery/capture.rs)
uses explicit little-endian fields, tags, version, lengths and CRC, never raw Rust
structure layout. Decode validates capacities, enums, handle ranges and independent
service/characteristic/descriptor/value relationships. Borrowed views serve both
saved rendering and host export. Unknown schemas and malformed data fail explicitly.

The [journal](../../crates/dashboard-core/src/discovery/capture_store.rs) provides
four slots, two 12 KiB copies per slot, maximum 8192-byte payloads and generation
counters that do not wrap. Header and commit CRCs bind the selected slot/copy,
generation, payload length and payload CRC. The inactive copy is verified before
commit; ambiguous generations and unknown schemas never trigger automatic erase.
Explicit local Reset erases only the selected slot. A readable supported sibling
can still load while unknown format blocks replacement.

Firmware reuses the [shared flash guard](../../firmware/pico2/src/flash_guard.rs)
and bounded [probe maintenance](../../firmware/ble-probe/src/maintenance.rs).
Each sector erase/page program obtains its own maintenance ticket; buffers and
hardware owners are retained through completion. This source contract does not
establish physical power-loss behavior or flash endurance.

## Build identity and preserved gates

The checked wrapper hashes the sorted compact JSON source inventory and supplies
`BLE_PROBE_SOURCE_DIGEST` after the snapshot. Inherited identity/compiler overrides
are removed in the child environment. A unique allocated read-only 32-byte linked
object must match the manifest digest in full artifact admission. ELF-only CI may
report unavailable identity and explicitly does not admit a source-bound UF2.
The section must be allocated, read-only and non-executable; LLVM may also set
`SHF_GNU_RETAIN` for the retained identity object. That retention flag is accepted
explicitly, while write, execute and unknown flags remain rejected. See the
[LLVM ELF flag definitions](https://www.llvm.org/docs/doxygen/BinaryFormat_2ELF_8h.html).
Source inventory identity is not complete compiler-input closure, a signature,
or firmware self-verification.

Probe program flash ends at `0x101E6000`; captures occupy the next 96 KiB and
settings retain the final 8 KiB of the conservative 2 MiB contract. The gate checks
all physical LOAD images, erase/verification ranges and canonical UF2 pages.
Both full and ELF-only paths invoke the existing exact reviewed pause/FIFO/JEDEC/
write-code checker. No flash-helper digest allowlist was regenerated for capture.

The existing 64 KiB core-0 headroom, 8 KiB largest emitted frame, 20 KiB aggregate
frame and 12 KiB non-radio aggregate guards remain. Storage and both USB tasks
are added to required named stack roots; core-1 retains its 32 KiB stack and
4 KiB reserve. These are conservative software admission rules, not physical
stack high-water measurements. A fresh linked image must pass them.

The checked probe wrapper and CI use `cargo rustc --bin ble-probe` with
`-C llvm-args=--inline-threshold=100000` for the final binary invocation only.
The normal Cortex-M33 flags and dependency compilation settings remain unchanged.
[Cargo documents this argument scope](https://doc.rust-lang.org/cargo/commands/cargo-rustc.html);
[LLVM documents the inlining control](https://llvm.org/docs/doxygen/InlineCost_8cpp.html).
This is a measured choice for the pinned compiler, not a portable performance
guarantee. It reduces emitted helper frames but increases code size and compile
work. Both stock and 280/70 images must still pass all original limits and exact
reviewed flash-helper byte checks. The manifest records the complete command and
separate binary options; the dashboard uses its existing build configuration.

The radio future is constructed in its task storage and polled through a small
borrowed, non-inlined radio boundary. This keeps genuine radio work separate from
the executor/metrics frame without moving or recreating the pinned owner. The
review compared the resident caller plus helper, not the smaller caller alone:
the diagnostic 280 image used 72 + 1504 bytes versus the previous combined
1536-byte frame, a 40-byte increase. That boundary is ownership organization,
not a stack-saving claim. Its descendants remain counted by the unchanged global
aggregate and radio allowance. A rejected async-constructor boundary produced a
12968-byte temporary; it is not in the implementation. Current source-bound image
receipts, rather than these diagnostic experiments, determine release admission.

## Verification scope

Focused host regressions cover independent binary fixtures, truncation and
corruption, maximum-capacity records, invalid relationships, interruption at
journal operation boundaries, reset isolation, read-only command parsing,
fragmented/error/timed-out responses and unique no-overwrite publication.
Actual standalone CLI linking and its help path are checked without opening ports.
Python regressions cover linked identity and reserved-range mutations, required
stack roots, unavailable ELF-only identity and propagation of flash-gate rejection.
Ruff and the configured production-boundary Mypy scope remain enabled.

These software checks do not qualify USB enumeration/cancellation on the device,
physical flash interruption, RF interoperability, electrical margins, scanout,
true stack maxima or NGM/OBDeleven/DNUC compatibility. Current image receipts and
CI results must be associated with the exact delivered commit; earlier probe
memory figures are historical. Export saves before arbitrary firmware replacement.
See [user workflow and format limits](../vehicle/ble-probe-captures.md) and
[adapter evidence boundaries](../vehicle/adapter-research.md).
